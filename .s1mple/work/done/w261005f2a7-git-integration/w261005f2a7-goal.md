## Execution Contract

- **Goal:** so shows and acts on Git state the LazyVim way. Inside a repository it shows gutter signs in their own change column, hunk navigation, preview, stage and reset, a statusline Git segment, explorer markers, and line blame. One key hands the terminal to lazygit and returns to an editor that reflects the new disk and Git state. Outside a repository every surface is byte-identical to v1.
- **Scope:** Every task in the three plan parts, in plan order: `DES1`–`DES13`, `S1`–`S36`, `V1`–`V47` and `V50`–`V69`, `UDES1@R1`–`UDES12@R1`, `US1@R1`–`US12@R1`, `UV1@R1`–`UV18@R1`, the `.s1mple/docs/project.md` update, and delivery per `.s1mple/S1MPLE.md`.
- **Non-goals:** Commit, push, pull, unstage, and branch operations inside so (lazygit owns them). Also out of scope: inline blame, `.git-blame-ignore-revs`, stage/reset keys in the hunk float, a `D` explorer marker or ghost rows, bar-style signs, polling fallback, non-EOL `.gitattributes` filters, JS Git libraries, new npm dependencies, release tags or publishing, and merging the PR.
