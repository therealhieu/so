# Status line on the last row (LazyVim-style layout, the default)

## Context

Today so lays out the screen the Vim way:

```
row 0        bufferline
rows 1..h−3  windows / explorer / side panel   (height rows − 3)
row h−2      statusline
row h−1      command line: `:`/`/` typing, messages, cursor diagnostic, pending keys
```

The user wants LazyVim's layout as the **default** (no setting): the status line on the very last row and no command line row. noice.nvim does the same:
- the cmdline becomes a popup;
- messages become notifications;
- the editor gets the row back.

Agreed defaults:

| Old command-line content | New home |
|---|---|
| `:` / `/` / `?` typing + completions | popup docked just above the status line; completions float above it |
| Messages (`s.notifications.message`) | a borderless mini line, right-aligned on the row above the status line (noice's `mini` view); `toast()` events stay top-right toasts |
| Cursor diagnostic in Normal mode | dropped; end-of-line diagnostics and `<C-w>d` already cover it |
| Pending keys (`s.vim.pending`) | right side of the status line, before `Ln:Col` (Neovim `showcmdloc=statusline`) |

```
┌──────────────────────────────────┐
│ main.rs                          │  row 0: bufferline
│ editor text                      │
│ editor text                      │  body: rows 1..h−2 (one more row than today)
│ editor text  Reloaded from disk  │  message: right end of the last body row
│ NORMAL │ main.rs │ ◆ rust-an  "d │  row h−1: statusline, pending keys on the right
└──────────────────────────────────┘
```

## Design

### 1. One source of truth for chrome rows
Add `src/core/state/layout.ts`:

```ts
/** The bufferline (row 0) and the statusline (the last row) frame the body. */
export const statusRow = (t: TerminalState) => Math.max(0, t.rows - 1);
/** Rows between the bufferline and the statusline. */
export const bodyRows = (t: TerminalState) => Math.max(0, t.rows - 2);
```

**Core:** the viewport stays `rows − 2`. Today that number was "statusline + command line"; now it is "bufferline + statusline", which equals the window height. That fixes an old mismatch: the core assumed one more row than the window had, and `text-view.ts` scrolled further to make up for it. Replace each literal with `Math.max(1, bodyRows(t))`:
- `src/core/state/keys.ts:228` (`envOf`, fix its comment);
- `src/core/state/buffers.ts:147` and `:508`;
- `src/ui/editors/text-view.ts:349` (`coreRows`, and simplify its comment);
- `src/core/state/zoom.ts:22`.

**UI body**: `rows − 3` becomes `bodyRows(t)` in:
- `window-tree.ts:81`
- `explorer.ts:119`
- `side-panel.ts:81`
- `notify.ts:41`
- `conflict.ts:174`

**Floats** whose room runs down to the statusline: `below = rows − 2 − (at.y+1)` becomes `statusRow(t) − (at.y+1)` in `completion.ts:74` and `lsp-float.ts:92`. `host.ts:43` `centered` and `picker.ts:48` use `bodyRows`.

`src/ui/widgets/base.ts:601` uses the widget's own rect, not the terminal, so it is unchanged.

### 2. Statusline (`src/ui/views/statusline.ts`)
- `top` and `targetAt` use `statusRow(t)`. The doc comment now says "the last row".
- Pending keys `s.vim.pending.join("")` are drawn right-aligned in `statusDim`, just left of `Ln:Col`.
  - They count toward `fixedWidth()`, so optional segments drop first. They are never dropped themselves.

### 3. Command line becomes a popup (`src/ui/views/cmdline.ts`)
- It paints and takes clicks **only while `s.vim.mode === "cmdline"`**; otherwise `visible = false`.
- Box: a framed `drawFrame` box (`floatBorder` / `float`) spanning the full width, with its bottom border on the row just above the status line (`statusRow − 1`). The text row is therefore `statusRow − 2`.
  - Text is scrolled as today so the cursor stays visible.
  - `cursorAt.y` is that text row.
- Completions keep `paintList`, but `top = popupTop − listH`.
- Remove the message, cursor-diagnostic and pending-key branches, and the now-unused `SEVERITY`/`MESSAGE_TOKEN` tables.
  - If `cursorDiagnostic` in `core/state/lsp.ts` has no other caller, remove it and its tests too (knip flags it).
- Update the class doc comment.

### 4. Messages become a mini line (`src/ui/views/cmdline.ts`)
- Core is unchanged: `message()` sets `s.notifications.message` and the next key clears it.
- Outside cmdline mode the view draws the message right-aligned on the row above the statusline (`statusRow − 1`), with the message tokens, cut to the terminal width. Clicks on it are inert.
- Why not a toast: base cells and calendar days post a message on every move. As top-right toasts they covered the base toolbar on each key. The user chose the mini line on 2026-10-06.

### 5. Conflict overlay (`src/ui/overlays/conflict.ts:240`)
The key hint ` k keep mine  t take disk  q back…` used to sit on the cmdline row (`rows − 1`). It moves to the last body row (`statusRow − 1`). The diff takes `bodyRows − 1` rows, so the CONFLICT status line stays visible.

### 6. Mouse
`shell.ts` keeps its source order. The cmdline view returns `inert` only over the popup or list while typing. The statusline already covers the last row.
