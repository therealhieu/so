# Base views: filter rows in the UI

## Context

Today a base table can only be filtered by writing `filters:` in the `.base` file. The UI offers just `f` (`base.filter`), which switches the view's own filters on or off. Users need to narrow rows from inside the table without editing YAML.

Decisions made with the user on 2026-10-10:
- **Scope:** UI filters belong to the window only. Like the window's sort, grouping and widths (`BaseUi`), they are never written to the `.base` file, and they disappear when the window closes.
- **Interactions:** a quick text filter, plus a filter on the focused cell's value. No expression input.

Work happens on the current branch `fix/review-and-fix`, as the user asked.

## UX

| Key | Command | Behaviour |
|---|---|---|
| `/` | `base.search` | Opens a filter input in the toolbar. As you type, rows stay only if some visible cell contains the text (case-insensitive). `⏎` keeps the text and closes the input. `esc` clears the text and closes the input. |
| `F` | `base.pin` | Keeps only rows whose focused column equals the focused cell's value. Pins on different columns stack (AND). Pressing `F` again on a cell whose value is already pinned removes that pin. |
| `c` | `base.clearFilters` | Clears the text filter and every pin. |

- **Matching:** pin matching reuses the evaluator's group keys (`groupKeys` / `stringifyGroupKey`, `src/core/features/bases/evaluator.ts:359`).
  - A scalar matches by equality.
  - A list cell (tags, lists) keeps rows whose list contains every pinned item.
  - An empty cell keeps rows where that column is empty.
- **Order:** UI filters run after the base's global and view filters and before `limit`, so a limited view still finds matches beyond its first N rows.
- **Board views:** both filters apply there too, because filtering happens in the evaluator before layout. `F` on a board card pins the board's group property value. `/` works the same way.
- **Toolbar:** shows `⌕ <text>` and `⊜ <column>=<value>` (clipped, like the existing `⧩` part). The row count reflects the filtered result.
- **Empty result:** when filters hide every row, the empty message says `c clears the filters`.
- **Hint line:** gains `/ search · F pin`. The `/` input has its own editing hint, like cell edits.

## Implementation

### 1. Types — `src/core/features/bases/types.ts`, `src/core/features/bases/file-type.ts`
- Extend `BaseUi` with:
  - `query?: string`
  - `pins?: readonly { column: string; keys: readonly string[] }[]`
- Extend `BaseWindowState` with:
  - `query?: string`
  - `pins?: { column: string; keys: string[] }[]`
  - `search?: { value: string; caret: number }` — the open input; while it is open, `query` mirrors `value`.
- Update the `BaseWindowState` doc comment.
- When the view changes, drop `query` and `pins`, the same way `widths` is dropped (the columns differ between views). Check where `widths` is reset and mirror it.

### 2. Evaluator — `src/core/features/bases/evaluator.ts`
- In `evaluateBase`, after `globalMatches` / `viewMatches`, build the row's cells and then drop rows that fail `matchesUi(cells, rawValues, ui)`:
  - **Query:** keep the row if some column's cell text, lowercased, contains the lowercased query. Reuse `cellText` (`src/core/features/bases/table.ts:130`). If importing it would create an import cycle, move it into a small shared module instead of duplicating it.
  - **Pins:** for each pin, `groupKeys(resolveColumnValue(...))` for the row must include every key in `pin.keys`. A pin whose column is not in `columns` is ignored.
- Keep `applyUi` as it is: UI filters are a separate row predicate, not a `BaseFilter`.

### 3. Model — `src/core/state/base-model.ts`
- `uiOf` passes `query` and `pins` through.
- `BaseViewModel` adds `query?: string` and `pins?: { label: string; text: string }[]` for the toolbar, with labels taken from the table columns.

### 4. Commands and keys — `src/core/state/base-commands.ts`
- `base.search`: sets `ws.search = { value: query ?? "", caret }`.
- `base.pin`:
  - **Table:** takes the focused column's id and computes keys from the focused row's raw value. Adding an identical pin again removes it.
  - **Board:** pins the group property with the focused card's lane key.
  - Echoes `pinned status = todo` or `unpinned …`.
- `base.clearFilters`: removes `query`, `pins` and `search`, and echoes `filters cleared`.
- Add bindings `/`, `F`, `c` to `KEYS`.
- `searchKey(s, a)`: a key handler shaped like `cellEditKey`.
  - Characters, `<BS>`, `<Left>` and `<Right>` edit `value` and set `query` live.
  - `<CR>` closes the input and keeps `query`.
  - `<Esc>` closes the input and clears `query`.
- Export `searchingBase(s)` next to `editingCell`.
- **Focus:** after a filter change, focus follows the focused note's path if it is still visible. Otherwise it clamps to the row index. `baseViewModel` already does this.

### 5. Key routing — `src/core/state/keys.ts:112`
- Next to `if (editingCell(s)) return cellEditKey(...)`, add `if (searchingBase(s)) return searchKey(...)`.
- `src/core/state/status.ts:119`: report `insert` mode while `search` is open, as it already does for `edit`.

### 6. View — `src/ui/editors/base-view.ts`
- `statusOf` adds the query and pin parts after `⧩`, and they drop out under the same `noFilter` / `short` fallbacks.
- While `ws.search` is open, draw the input on the toolbar row with a line cursor at the caret. Reuse the `cells()` caret math from the cell edit (`base-view.ts:103-150`).
- `hintOf`: a search hint (`search — ⏎ keep · esc clear`). The table hint gains `/ search · F pin`.
- Empty-state message (`base-view.ts:238`, `src/ui/widgets/base.ts:278`): when `query` or `pins` are set, say `c clears the filters`.

## Changes from the plan during implementation

- Pins are keyed by **property** (`BasePin { property, keys }`), not column id. A table pin uses the focused column's property and a board pin uses the group property, so both paths share one evaluator check. A property no note holds counts as empty.
- The open filter input is drawn vim-style on the **hint row** (`/text`, with `⏎ keep · esc clear` on the right), not in the toolbar.
- The table hint reads `f / F filter` so that `⏎ open` still fits in 80 columns.
- `stringifyGroupKey` and `cellText` moved to `src/core/features/bases/values.ts`, so the evaluator can match text without an import cycle with `table.ts`.
- Pins are checked after the cells are validated, so diagnostics don't change with the UI filters.
