## 1. Decisions

- **Prompt:** Support kitty's OSC 66 text sizing in `so`: bigger H1/H2 headings and half-size math and footnote scripts, falling back to today's drawing where the terminal can't do it.
- **Goal:** In kitty, H1 shows at 2× and H2 at 1.5× (2 rows each) in the `reading` and `live` views, and `Q_{w}` shows as `Q` with a small `w`; in any other terminal, or inside a multiplexer that drops OSC 66, every screen looks exactly as it does today.
- **Scope:** headings H1–H2 in Markdown notes (`reading`, `live`); math blocks and inline math; footnote references and definition labels; a `preview.sizedText` setting · **Non-goals:** H3 and deeper (unchanged), note embeds, callout titles, table cells (keep `mathText`), the `source` view, the browser preview, any other file type.
- **UI:** `not needed — the look was settled on 2026-10-19 in the preview artifact https://claude.ai/artifact/98MQ6bD644M9ZnRJcXrgwg (preset A)`

```text
today   # Raft  →  "█ Raft" in 1 row          Q_{w}  →  "math: unsupported TeX shown as source"
after   # Raft  →  2× text in 2 rows (kitty)  Q_{w}  →  Q + half-size w in 1 cell (kitty)
        anything else → today's output, byte for byte
```

### System Design

| ID | Decision | Builds | Why |
|---|---|---|---|
| `DES1` | **Capability and setting.** `ViewHost.sizedText: boolean` (`src/core/state/view-context.ts`), set by the UI to `renderer.capabilities?.scaled_text === true` (tests inject it through `ShellDeps.capabilities`). `PreviewCtx.sizedText = host.sizedText && config.preview.sizedText` (`markdown-view.ts`). `preview.sizedText: z.boolean().default(true)` in `ConfigSchema`, plus a `SETTINGS` entry. The shell repaints on OpenTUI's `capabilities` event, since support is known only after the first frame. | `REQ2`, `REQ6` | One switch for the core; OpenTUI already detects support (`A1`). |
| `DES2` | **Sized heading layout (core).** When `ctx.sizedText`, the heading renderer replaces an H1/H2 line with a block widget `{ type: "sizedText", rows: 2 × wrapped rows, data: SizedBlock }`, `SizedBlock = { scale: 2 \| 1.5; rows: SizedChunk[][] }`, `SizedChunk = { text; style; under?; cells }`. Its spans come from the line's own heading and inline decorations through `layoutLine`, exported from `src/core/kernel/view/text-view.ts`. A pure `src/core/kernel/view/sized.ts` makes the chunks and wraps them: scale 2 → each same-style run is one chunk, `2 × width` cells; scale 1.5 → same-style runs of at most 4 cells, each `2 × ceil(1.5 × width / 2)` cells. Rows break at spaces, else mid-word, within the window's text width. `RenderCache` keys include `sizedText`. | `REQ1`, `REQ2` | A widget reserves rows the way images do, so scrolling, mouse, and cursor code stays as it is. |
| `DES3` | **Reveal keeps height.** `livePreview` adds, below a revealed line whose block is a sized heading, a block widget (`at.col > 0`, drawn below its line) of `rows − 1` blank rows. | `REQ4` | The lines below never jump when the cursor enters or leaves a heading. |
| `DES4` | **Half-size scripts (core).** `Span.script?: { text: string; place: "sup" \| "sub" }` in `src/core/kernel/view/types.ts`: the span's `text` is the pair's first character (one narrow cell), `script.text` holds 1–2 characters. `mathRuns(tex)` in `math.ts` parses like `mathText`, but returns runs where any character can be a script (nested scripts flatten to one level). Block and inline math use it when `ctx.sizedText`; tables keep `mathText`. Footnote references (`inline.ts`) and definition labels (`footnote.ts`) become `sup` script spans for any label when `ctx.sizedText`. A script containing a wide character keeps today's output. | `REQ2`, `REQ5` | One cell per pair keeps every kernel width rule unchanged (`A8`). |
| `DES5` | **Writer (`src/ui/sized-text.ts`, `SizedText`).** Views register this frame's blocks and script cells while rendering. A renderer post-process step (after every renderable, before OpenTUI's diff): (1) a block is *covered* when any cell in its area differs from what its painter drew, and is not drawn; (2) every block written last frame that is not drawn identically this frame has its area marked changed in `currentRenderBuffer`, so OpenTUI rewrites it top row first; (3) a block is drawn when it is new, moved, or changed, when OpenTUI will write into its area, or after a resize or resume. On the `frame` event, everything goes out in one `writeOut`: `CSI ?2026h`, `ESC 7`, then for each chunk `CUP` + SGR + `OSC 66 ; s=2[:w=N:n=3:d=4:v=2] ; text ST`, and for each script cell `CUP` + SGR + `OSC 66 ; n=1:d=2:v=0\|1:w=1 ; text ST`, then `ESC 8` and `CSI ?2026l`. | `REQ1`, `REQ3`, `REQ5` | Follows kitty's overwrite rules (`A5`) without changes to OpenTUI. |
| `DES6` | **Painters.** The `sizedText` widget painter paints the heading background over all its rows and the text at normal size on the first row. It registers the block only when given all its rows; cut at the window bottom, the normal-size text stays. `paintLine` registers the cell of each `script` span it draws, with its style. | `REQ1`, `REQ3`, `REQ5` | The normal-size text shows wherever sized text cannot be drawn. |

#### Test Strategy

Aim for the fewest cases that catch the failures that matter. Test count is not a goal.

- **Prioritize:** the layout contract (rows reserved = rows drawn), the exact OSC 66 bytes, the redraw and erase decisions against kitty's overwrite rules, and the fallback staying byte-identical.
- **Skip:** theme colour lookups, OpenTUI's own capability probe, and repeating the existing heading, math, and footnote tests for the non-sized path (they keep passing unchanged).
- **Prove once:** layout in core unit tests; bytes in a UI unit test; frame decisions in one component suite; no-support in one PTY test; how it looks only by hand in kitty, the only terminal here that draws OSC 66.
- **Use the project's layers:** no new tooling; xterm headless covers the "no support" side.
- **UI:** the manual kitty check covers the main journeys (scroll, float, resize, hand-off, reveal) and the herdr setup the user runs.
